# Блиц: ООП и разработка ПО для Data Engineer

Тренировочный список для ответа за 30–60 секунд. Добавляйте пример из своего проекта и одну границу применимости. Подробные разборы: [ООП](../01-junior/06-oop-for-data-engineers.md), [разработка ПО](../02-middle/13-software-engineering-for-data-engineers.md), [хеши](../02-middle/14-hashing-and-deduplication.md).

## ООП и Python

| № | Вопрос | Короткий ответ и пример |
|---|---|---|
| 1 | Класс и экземпляр — в чём разница? | Тип загрузчика и конкретный загрузчик CRM со своим состоянием. |
| 2 | Что скрывает инкапсуляция? | Детали соединения за `read()`; `_field` — соглашение, а не защита секрета. |
| 3 | Где есть полиморфизм в ETL? | `pipeline(source)` работает с CSV- и API-источником через один договор. |
| 4 | Композиция или наследование? | Operator наследует BaseOperator и использует Hook. |
| 5 | Зачем dependency injection? | Подставить FakeReader и проверить обработку без API. |
| 6 | `Protocol` или ABC? | Структурный договор для проверки типов против абстрактного базового класса с обязательными методами. |
| 7 | Как выглядит нарушение LSP? | Наследник Writer сообщает об успехе, молча пропуская строки. |
| 8 | Почему атрибут `rows = []` опасен? | Экземпляры могут модифицировать один общий список класса. |
| 9 | Что делает `classmethod`? | Получает `cls`; фабрика `from_config()` создаёт экземпляр класса вызова. |
| 10 | `__new__` против `__init__`? | Создание объекта против инициализации уже созданного. |
| 11 | Что делает `super()` при нескольких родителях? | Следует MRO; это не всегда вызов прямого родителя. |
| 12 | Равные объекты обязаны иметь одинаковый хеш? | Да; обратное неверно. Хеш ключа должен оставаться стабильным. |
| 13 | Почему `frozen=True` не даёт глубокую неизменяемость? | Вложенный список остаётся изменяемым; такой ключ может быть нехешируемым. |
| 14 | Что решает `with`? | Управляемое завершение работы с ресурсом; договор закрытия зависит от библиотеки. |
| 15 | GIL защищает от всех гонок? | Нет: проверка и запись — несколько шагов, а другие процессы имеют своё состояние. |

## Надёжность и процесс разработки

| № | Вопрос | Короткий ответ и пример |
|---|---|---|
| 16 | Как отделить I/O от логики? | Reader/Writer работают с внешними системами, Transform принимает и возвращает значения. |
| 17 | Unit-тест доказывает корректность SQL? | Нет; нужен integration-тест на подходящей СУБД. |
| 18 | Типизация проверяет входной JSON? | Нет; runtime-валидация проверяет фактический вход. |
| 19 | Можно ли повторить запрос после timeout? | Только с учётом неизвестного исхода и механизма идемпотентности. |
| 20 | Зачем backoff и jitter? | Снизить нагрузку и рассинхронизировать повторные обращения. |
| 21 | Что нужно кроме `MERGE`? | Договор ключа, выбор версии, дедупликация источника, транзакции и защита от конкуренции. |
| 22 | Почему DB commit перед offset commit даёт повтор? | Сбой между ними приводит к повторному чтению; batch ledger/dedup предотвращает повторный эффект. |
| 23 | Что гарантирует outbox? | Совместную запись бизнес-изменения и сообщения в локальной транзакции; relay может дублировать. |
| 24 | Почему нельзя проверять backfill только по success? | Нужны сверка, изоляция от live-запуска и управляемая публикация. |
| 25 | Как безопасно убрать колонку? | Expand → переход потребителей и backfill → contract. |
| 26 | Threads или processes? | I/O допускает threads/asyncio; CPU-bound Python в обычной GIL-сборке часто требует processes/нативного движка. |
| 27 | Зачем bounded queue? | Ограничить память и передать давление назад к источнику. |
| 28 | Как измерить успешность конвейера? | Freshness, полнота, корректность и доступность потребителю вместе со статусом задачи. |
| 29 | Хватит ли Git для воспроизводимости? | Нужны версии зависимостей, конфигурации и входных данных. |
| 30 | Почему нельзя распаковывать чужой pickle? | Десериализация может выполнить код; используйте подходящий безопасный формат обмена. |

## Четыре схемы для объяснения вслух

```text
1. Граница кода:   Orchestrator → Reader → Transform → Writer
2. Повтор:        запись → сбой до подтверждения → повтор → dedup → один эффект
3. Выпуск схемы:  добавить v2 → переключить потребителей → проверить → удалить v1
4. Давление:      1000 строк/с → bounded queue → 600 строк/с → замедлить чтение
```

Для самопроверки объясните, какие данные и метрики подтвердят корректность каждой схемы. Далее: [общие DE-вопросы](common-de-interview-questions.md) и [памятка](interview-preparation-memo.md).
