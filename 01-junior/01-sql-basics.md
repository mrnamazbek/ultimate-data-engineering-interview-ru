# Базовый SQL для Data Engineer (Уровень Junior)

Данный модуль содержит ключевые вопросы и ответы по базовому SQL, встречающиеся на технических собеседованиях на позиции Junior Data Engineer и Junior Database Developer. Материал основан на анализе практических собеседований и структурирован по принципу: от простого понимания концепции к реальным задачам бизнеса.

## 1. Порядок выполнения SQL-запроса (SQL Order of Execution)

### Кратко: что это и зачем нужно
СУБД выполняет этапы запроса не в том порядке, в котором они написаны в тексте запроса. Понимание порядка выполнения критично для оптимизации запросов и понимания того, почему, например, алиасы из `SELECT` нельзя использовать в `WHERE`.

### Логический порядок выполнения
1. `FROM` и `JOIN` — определение таблиц-источников, объединение и построение декартова произведения/соединений.
2. `WHERE` — строковая фильтрация данных до агрегации.
3. `GROUP BY` — группировка строк по указанным столбцам.
4. `HAVING` — фильтрация сгруппированных данных по результатам агрегатных функций.
5. `SELECT` — выборка колонок, вычисление выражений, присвоение псевдонимов (алиасов).
6. `DISTINCT` — устранение дубликатов из результирующего набора.
7. `ORDER BY` — сортировка итогового набора строк.
8. `LIMIT` / `OFFSET` (`TOP`) — ограничение количества возвращаемых строк.

### Практический пример
```sql
SELECT 
    department_id, 
    AVG(salary) AS avg_sal
FROM employees
WHERE status = 'ACTIVE'
GROUP BY department_id
HAVING AVG(salary) > 100000
ORDER BY avg_sal DESC
LIMIT 5;
```

### Частая ошибка на собеседовании
Попытка использовать псевдоним из `SELECT` в блоке `WHERE`:
```sql
-- ОШИБКА: колонка bonus_amount еще не вычислена на этапе WHERE
SELECT salary * 0.1 AS bonus_amount
FROM employees
WHERE bonus_amount > 5000;

-- ПРАВИЛЬНО:
SELECT salary * 0.1 AS bonus_amount
FROM employees
WHERE (salary * 0.1) > 5000;
```

## 2. Разница между DELETE, TRUNCATE и DROP

| Характеристика | DELETE | TRUNCATE | DROP |
|---|---|---|---|
| Тип команды | DML (Data Manipulation) | DDL (Data Definition) | DDL (Data Definition) |
| Что удаляет | Отдельные строки (по условию `WHERE`) | Все строки из таблицы | Всю таблицу вместе со структурой и метаданными |
| Скорость | Медленно (построчная запись в журнал транзакций) | Быстро (освобождает страницы данных целиком) | Мгновенно |
| Условие WHERE | Поддерживается | Не поддерживается | Не поддерживается |
| Откат (ROLLBACK) | Да, в рамках активной транзакции | В большинстве СУБД (PostgreSQL, MS SQL) откатывается, если внутри транзакции | В некоторых СУБД откат невозможен (автокоммит DDL в MySQL/Oracle) |
| Сброс автоинкремента | Не сбрасывает счетчик `IDENTITY` / `AUTO_INCREMENT` | Сбрасывает счетчик к начальному значению | Таблица перестает существовать |
| Триггеры | Вызывает триггеры `ON DELETE` | Не вызывает строчные триггеры удаления | Не вызывает триггеры строк |

### Пример
```sql
-- Удалить неактивных клиентов (DML)
DELETE FROM clients WHERE is_active = FALSE;

-- Быстро очистить временную буферную таблицу в ETL-пайплайне (DDL)
TRUNCATE TABLE staging_events;

-- Полностью удалить устаревшую витрину данных (DDL)
DROP TABLE IF EXISTS legacy_report_2022;
```

## 3. Разница между WHERE и HAVING

### Кратко
- `WHERE` фильтрует строки **до** выполнения группировки и вычисления агрегатных функций.
- `HAVING` фильтрует группы строк **после** выполнения `GROUP BY` и расчета агрегатов (`COUNT`, `SUM`, `AVG` и т.д.).

### Пример
```sql
-- Найти категории товаров, у которых на складе более 10 активных позиций, 
-- а средняя цена товара в категории выше 5000
SELECT 
    category_id,
    COUNT(*) AS total_items,
    AVG(price) AS average_price
FROM products
WHERE is_available = TRUE          -- фильтр отдельных строк (WHERE)
GROUP BY category_id
HAVING COUNT(*) > 10               -- фильтр агрегированных групп (HAVING)
   AND AVG(price) > 5000;
```

### Совет по оптимизации
Всегда переносите условия, не требующие агрегации, из `HAVING` в `WHERE`. Это сокращает объем данных, передаваемых на этап группировки, экономя память и процессорное время.

## 4. Виды соединений таблиц (JOIN)

1. **INNER JOIN** — возвращает только те строки, для которых найдено совпадение условий в обеих таблицах.
2. **LEFT (OUTER) JOIN** — возвращает все строки из левой таблицы. Если в правой таблице совпадений нет, подставляются значения `NULL`.
3. **RIGHT (OUTER) JOIN** — возвращает все строки из правой таблицы и совпадающие из левой.
4. **FULL (OUTER) JOIN** — возвращает все строки из обеих таблиц, дополняя отсутствующие стороны значениями `NULL`.
5. **CROSS JOIN** — декартово произведение, каждая строка первой таблицы соединяется с каждой строкой второй таблицы (размер = N * M).
6. **SELF JOIN** — объединение таблицы с самой собой. Типичный сценарий: иерархии (сотрудник и его руководитель в таблице `employees`).

### Пример SELF JOIN
```sql
-- Таблица сотрудников: id, name, manager_id
SELECT 
    e.name AS employee_name,
    m.name AS manager_name
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
```

## 5. UNION против UNION ALL

### Кратко
Оба оператора объединяют результаты двух и более запросов по вертикали.
- `UNION` выполняет дополнительную операцию дедупликации (сортировку или построение хэш-таблицы для удаления одинаковых строк).
- `UNION ALL` просто склеивает наборы строк без проверки на дубликаты.

### Влияние на производительность в Big Data
В конвейерах данных при объемах в миллионы и миллиарды строк `UNION` вызывает тяжелый Shuffle и сортировку. Если гарантируется уникальность источников или дубликаты допустимы, всегда используйте `UNION ALL`.

```sql
-- Быстрое объединение двух источников данных в хранилище
SELECT user_id, event_time, 'mobile' AS platform FROM mobile_logs
UNION ALL
SELECT user_id, event_time, 'web' AS platform FROM web_logs;
```

## 6. Первичный и внешний ключи (PRIMARY KEY vs FOREIGN KEY)

- **PRIMARY KEY (Первичный ключ)**:
  - Уникально идентифицирует каждую запись в таблице.
  - Не может содержать значений `NULL`.
  - В таблице может быть только один первичный ключ (он может быть составным — состоять из нескольких полей).
  - По умолчанию в большинстве СУБД создает кластерный или уникальный B-Tree индекс.

- **FOREIGN KEY (Внешний ключ)**:
  - Ссылается на первичный или уникальный ключ другой таблицы.
  - Обеспечивает ссылочную целостность данных (Referential Integrity).
  - Может содержать дубликаты и значения `NULL` (если столбец не объявлен как `NOT NULL`).

## 7. Работа со значениями NULL и трехзначная логика

### Суть концепции
В реляционных базах данных `NULL` означает отсутствие значения («неизвестность»), а не ноль или пустую строку. Логические операции с `NULL` возвращают `UNKNOWN`.

- `NULL = NULL` вернет `UNKNOWN` (не `TRUE`).
- Для проверки наличия `NULL` необходимо использовать операторы `IS NULL` или `IS NOT NULL`.

### Функции обработки NULL
- `COALESCE(val1, val2, ...)` — возвращает первое значение из списка, отличное от `NULL`. Стандарт ANSI SQL.
- `NULLIF(expr1, expr2)` — возвращает `NULL`, если `expr1 = expr2`, иначе возвращает `expr1`. Защищает от ошибки деления на ноль.

### Пример защиты от деления на ноль
```sql
-- Если total_orders = 0, NULLIF вернет NULL, и результат деления станет NULL, а не выбросит исключение Division by zero
SELECT 
    total_revenue / NULLIF(total_orders, 0) AS avg_order_value
FROM daily_metrics;
```

## 8. Подзапросы: IN против EXISTS

### Кратко
- `IN` оценивает весь список значений внутреннего подзапроса. Если в результатах подзапроса присутствует `NULL`, `NOT IN` может вернуть пустой результат из-за трехзначной логики.
- `EXISTS` останавливает поиск при первом же совпадении (механизм Short-circuit evaluation), проверяя лишь факт наличия хотя бы одной строки.

```sql
-- Эффективный поиск клиентов, совершивших заказы
SELECT c.customer_id, c.customer_name
FROM customers c
WHERE EXISTS (
    SELECT 1 
    FROM orders o 
    WHERE o.customer_id = c.customer_id
);
```

## 9. Нахождение дубликатов в таблице

Классическая задача на собеседовании Junior Data Engineer:

```sql
-- Поиск дублирующихся email-адресов и количества повторений
SELECT 
    email, 
    COUNT(*) AS occurrences
FROM users
GROUP BY email
HAVING COUNT(*) > 1;
```

Удаление дубликатов с сохранением одной записи с помощью обобщенного табличного выражения (`CTE`) и `ROW_NUMBER()`:
```sql
WITH RankedUsers AS (
    SELECT 
        id,
        email,
        ROW_NUMBER() OVER (PARTITION BY email ORDER BY id ASC) AS row_num
    FROM users
)
DELETE FROM users
WHERE id IN (
    SELECT id 
    FROM RankedUsers 
    WHERE row_num > 1
);
```

## 10. Поиск N-й максимальной зарплаты

### Способ 1: С использованием DENSE_RANK() (Рекомендуемый стандарт)
```sql
WITH SalaryRank AS (
    SELECT 
        employee_id,
        salary,
        DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM employees
)
SELECT salary 
FROM SalaryRank
WHERE rnk = 2; -- Вторая максимальная зарплата
```

### Способ 2: Через LIMIT и OFFSET (для MySQL / PostgreSQL)
```sql
SELECT DISTINCT salary
FROM employees
ORDER BY salary DESC
LIMIT 1 OFFSET 1; -- Вторая зарплата (пропуск 1 строки)
```

## Практические советы для собеседования
1. **Никогда не используйте `SELECT *` в продакшн-запросах**. Называйте только нужные столбцы — это критично для колоночных СУБД (ClickHouse, BigQuery, Snowflake) и снижает нагрузку на сеть и дисковый ввод-вывод.
2. **Помните разницу между `DISTINCT` и `GROUP BY`**. `DISTINCT` устраняет полностью идентичные строки результата, тогда как `GROUP BY` формирует группы для выполнения агрегатных расчетов.
3. **Объясняйте стоимость операций**. Упоминайте, что `UNION` требует дополнительной сортировки, а соединение таблиц без индексов приводит к тяжелому `Hash Join` или `Nested Loop` со сканированием всей таблицы (`Seq Scan`).
