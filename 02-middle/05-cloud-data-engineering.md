# Облачные платформы данных: Azure и Google Cloud (Уровень Middle)

В современных проектах большинство конвейеров данных разворачивается в публичных облаках. На собеседованиях для Middle Data Engineer фокус смещается на знание архитектуры облачных сервисов (**Microsoft Azure** и **Google Cloud Platform**), разграничение доступа, оптимизацию затрат на облачные вычисления и выбор подходящего инструмента под задачу.

---

## 1. Стек данных Microsoft Azure

### 1.1. Azure Data Factory (ADF)
ADF — управляемый облачный сервис оркестрации и интеграции данных без необходимости администрирования серверов.

#### Ключевые компоненты ADF:
- **Linked Service (Связанная служба)**: строка подключения к внешнему источнику или приемнику данных (например, подключение к PostgreSQL, Oracle, ADLS Gen2 или AWS S3 с хранением пароля в Azure Key Vault).
- **Dataset (Набор данных)**: описание структуры конкретного набора данных (путь к папке Parquet-файлов в контейнере или конкретная таблица в SQL).
- **Activity (Действие)**: шаг внутри конвейера (Copy Activity, Databricks Notebook Activity, Stored Procedure, Web Activity).
- **Pipeline (Конвейер)**: логическая группа действий, выполняющих единую бизнес-задачу.

#### Типы Integration Runtime (IR)
Integration Runtime — это вычислительная инфраструктура, на которой физически запускаются действия ADF:
1. **Azure IR**: полностью управляемый бессерверный пул ресурсов Microsoft. Подходит для перемещения данных между облачными источниками.
2. **Self-hosted IR**: программный агент, устанавливаемый инженером на собственный сервер или виртуальную машину внутри закрытого контура (On-premise). Необходим для безопасного забора данных из локальных корпоративных СУБД (Oracle, SAP, MS SQL) через корпоративный файрвол без открытия прямого публичного IP.
3. **Azure-SSIS IR**: выделенный кластер для запуска устаревших пакетов SQL Server Integration Services в облаке.

#### Типы триггеров в ADF:
- **Schedule Trigger**: запуск по календарному расписанию (например, каждый понедельник в 03:00).
- **Tumbling Window Trigger (Перекатывающееся окно)**: запускается через фиксированные непрерывные интервалы времени. Поддерживает обработку исторических срезов, зависимости между окнами и повторные попытки (Retry).
- **Storage Event Trigger**: запуск по событию появления или удаления файла в Azure Blob Storage.

### 1.2. Хранение данных: Azure Blob Storage против ADLS Gen2
- **Azure Blob Storage**: классическое плоское объектное хранилище (Object Storage). Иерархия папок эмулируется только слешами в именах файлов (`/folder/subfolder/file.csv`). При переименовании директории с 100 000 файлов Blob Storage вынужден скопировать все 100 000 объектов, что делает операции атомарного перемещения крайне медленными.
- **Azure Data Lake Storage Gen2 (ADLS Gen2)**: построено поверх Blob Storage, но имеет включенное **иерархическое пространство имен (Hierarchical Namespace)**. Директории являются реальными объектами файловой системы. Поддерживает списки управления доступом POSIX (ACLs) на уровне отдельных каталогов и файлов, что критично для безопасности Hadoop/Spark.

## 2. Стек данных Google Cloud Platform (GCP)

### 2.1. Google BigQuery: архитектура и оптимизация расходов
BigQuery — полностью бессерверное (Serverless) распределенное аналитическое хранилище данных с колоночным форматом хранения (Capacitor) и движком распределенного выполнения запросов (Dremel).

#### Разделение вычислений и хранения (Compute-Storage Separation)
Хранилище (Colossus) физически отделено от вычислительных узлов (Dremel Slots). Вы платите отдельно за объем хранимых терабайт и отдельно за объем данных, прочитанных вашим запросом с диска ($6.25 за 1 ТБ прочитанных данных в модели On-demand).

#### Партиционирование (Partitioning) и Кластеризация (Clustering)
На собеседовании обязательно проверяют понимание того, как не разорить компанию на запросах в BigQuery:

```sql
-- Создание таблицы с партиционированием по дням и кластеризацией по ID клиента
CREATE TABLE analytics.fact_orders (
    order_id STRING,
    customer_id INT64,
    order_date DATE,
    amount NUMERIC
)
PARTITION BY order_date
CLUSTER BY customer_id;
```

- **Partitioning (Партиционирование)**: физически разбивает таблицу на отдельные сегменты (по дате `order_date`, диапазону чисел или времени загрузки). При выполнении `WHERE order_date = '2026-09-18'` BigQuery сканирует **только одну партицию**, сокращая объем читаемых данных со 100 ТБ до 500 МБ.
- **Clustering (Кластеризация)**: сортирует данные внутри каждой партиции по указанным колонкам (до 4 колонок). Ускоряет точечные фильтрации и соединения (`WHERE customer_id = 101` или `JOIN on customer_id`).

### 2.2. Безопасность Google Cloud Storage (GCS)
Чек-лист безопасности для инженера данных:
1. Запрет публичного доступа: активация политики **Uniform bucket-level access** и удаление ролей `allUsers` и `allAuthenticatedUsers`.
2. Принцип наименьших привилегий (Least Privilege): назначение гранулярных IAM ролей (например, `roles/storage.objectViewer` вместо полного доступа `roles/storage.admin`).
3. Защита учетных записей: использование Service Account с привязкой через Workload Identity Federation вместо выгрузки небезопасных статических JSON-ключей на серверы.
4. Жизненный цикл данных (Lifecycle Rules): автоматический перевод старых файлов через 30 дней в архивные классы хранения (Nearline, Coldline, Archive) для снижения расходов.

---

### 2.3. Потоковая передача: Cloud Pub/Sub и Cloud Dataflow
- **Cloud Pub/Sub**: глобальный бессерверный брокер сообщений (аналог Apache Kafka в GCP). Обеспечивает асинхронную доставку событий между источниками и потребителями с гарантией доставки At-least-once.
- **Cloud Dataflow**: управляемый бессерверный движок для исполнения конвейеров **Apache Beam**. Позволяет писать единый код трансформации на Python или Java, который одинаково работает как в пакетном режиме (Batch), так и в непрерывном потоковом режиме (Streaming) с автоматическим масштабированием воркеров.
